# Research: Natural-Language Reminder Agent

## R1. Where the non-determinism lives

- **Decision**: The model does one job: read the sentence and fill the seven-field object. Everything
  else (pre-checks, parsing, validation, fallback) is ordinary deterministic code.
- **Rationale**: Keeps the untestable part as small as possible (Constitution II) and lets unit
  tests cover the rest without a network.
- **Alternatives considered**: Letting the model also decide whether its own output is valid
  (unverifiable); a rule-based date parser with no model (not a non-deterministic AI application,
  which Part 1B requires).

## R2. Model access

- **Decision**: Google Gemini through the public HTTPS `generateContent` endpoint, called with
  `urllib.request`; API key in the `x-goog-api-key` header; temperature 0; JSON response type
  requested. Model name from `GEMINI_MODEL`; when unset, the client lists the available models and
  picks the newest general-purpose "flash" model. The name actually used is recorded in every run.
- **Rationale**: No SDK dependency (Constitution VI). Model names change often, so the name is
  configuration, and recording it keeps results interpretable (EV-6).
- **Alternatives considered**: Google's Python SDK (adds a dependency); hard-coding one model name
  (breaks when that model is retired).

## R3. Date arithmetic

- **Decision**: The instructions include the reference moment, its weekday and a 15-day calendar
  (date + weekday name) generated by code.
- **Rationale**: Language models are unreliable at weekday arithmetic; giving them the calendar turns
  a calculation into a lookup. The reference moment is an input, so expected values are fixed (EV-7).
- **Alternatives considered**: Asking the model for relative expressions and computing dates in
  code (more code and a second contract to specify); trusting the model's arithmetic.

## R4. Handling the model's reply

- **Decision**: `parser.py` accepts a bare JSON object, or one inside a Markdown code fence, and
  nothing else. `validator.py` checks INV-1…INV-9. Any failure → unknown result (FR-014), with the
  reason kept in a diagnostics field that is outside the returned contract object.
- **Rationale**: The caller always receives a contract-valid object (SC-002); the harness still sees
  the failure because "unknown" will not match the expected result.
- **Alternatives considered**: Repairing the model's output field by field (hides model errors and
  invents data); retrying the model until it validates (costly, still not guaranteed).

## R5. Prompt-injection defence

- **Decision**: Two layers. (1) The instructions tell the model that the user's text is data and
  that any instruction aimed at the agent must yield the unknown result. (2) The instructions carry
  a unique marker; the validator rejects any result containing it (INV-9).
- **Rationale**: (1) addresses behaviour; (2) gives a deterministic, checkable leak property.
- **Alternatives considered**: Keyword block-lists before the model call (brittle; only added if
  evaluation evidence shows the model-level defence is insufficient).

## R6. Evaluation design

- **Decision**: One runner, three evaluator modules, rule-based L3 scoring against ground truth
  (intent, slot value, task key-word fraction). No LLM judge. Service failures are retried with
  back-off, then recorded as `service_error` and make the run INCOMPLETE (EV-5).
- **Rationale**: Ground truth is exact for intent and date-time, so a judge model would add
  non-determinism without adding information. The key-word fraction tolerates wording variation.
- **Alternatives considered**: LLM-as-judge for task fidelity (needs a second quota and its own
  validation); exact string match on the task (fails on harmless wording changes).

## R7. Testing the judge

- **Decision**: The three evaluator modules have their own unit tests with hand-written good and bad
  results, and the runner can be driven by a recorded-reply file (`--replay`) so the whole pipeline
  can be exercised offline. A replay run is labelled SELF-TEST and is never an evaluation result.
- **Rationale**: A harness that has never been seen to fail a bad output is not evidence.
